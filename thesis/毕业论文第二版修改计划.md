# 毕业论文第二版修改计划

## 一、修改目标

本次修改的目标不是对第一版做局部润色，而是参照《优秀模板2》的行文方式，对论文进行结构重构、论证补强和事实对齐，形成一份更接近正式毕业论文体例的第二版稿件。

第二版需要同时满足以下要求：

1. 结构上接近《优秀模板2》的“绪论—相关技术—核心方法—系统与实验—总结展望”路径。
2. 内容上与当前工作目录 `D:\graduation_thesis` 中的真实项目保持一致。
3. 方法论表述中将 LightRAG 视作论文中的 V-KG RAG 落地实现。
4. 实验结果以 `output\fixed_evaluation_progress.jsonl` 为最终准据。
5. 不重新运行任何测评接口，不在论文中体现分数修正逻辑。

## 二、总体修改策略

### 1. 结构重构

将原论文从“方案介绍型”结构，调整为“问题提出—技术铺垫—方法设计—系统实现—实验验证”结构。新的章节将更强调：

- 研究背景与研究空白
- 技术路线与研究目标
- LightRAG/V-KG RAG 的技术基础
- 果园病虫害问答任务中的方法设计
- 实验设计的规范性与结果分析的完整性

### 2. 事实对齐

对第一版中与当前项目不一致的工程描述进行统一，避免继续沿用旧设想。第二版将以以下事实为准：

- 基线方法：`pure_llm`、`naive_rag`、`light_rag`
- 对照工程：`main.py` + `methods/` + `evaluation/`
- 检索增强主方案：LightRAG，对应论文中的 V-KG RAG
- 向量检索基线：Embedchain + ChromaDB
- 生成模型：Qwen 系列兼容接口
- 评测模型：GLM-5
- 评测集：A 类事实型问题 20 个，B 类推理型问题 30 个

### 3. 写作风格调整

第二版将把第一版中偏“说明书式”的写法，改为更符合毕业论文的学术化表达方式，包括：

- 把“系统做了什么”改写为“问题—方法—结果”的叙述
- 增加章节导入段、本章小结、模块之间的衔接语
- 将关键机制写成可理解的流程化表达
- 对实验结果进行分层分析，而不只给出表格

## 四、各章修改重点

### 第一章修改重点

1. 将“研究背景及目的”拆解为更标准的背景、意义、问题引出结构。
2. 将“国内外研究现状”扩写为分类综述，不再只保留两段总述。
3. 单独补出“研究目标”“研究方法与技术路线”两节。
4. 让第一章完整回答三个问题：
   - 为什么要做
   - 别人做到了什么程度
   - 本文准备如何做

### 第二章修改重点

1. 从“系统整体架构与关键技术阐述”改成“相关技术与开发环境介绍”。
2. 补足 LLM、向量检索、RAG、LightRAG 的理论铺垫。
3. 对 LightRAG 的图增强索引、双层检索、增量更新、mix 查询模式进行更加规范的表述。
4. 将现有工程环境、模型配置、评测模块放入本章统一交代。

### 第三章修改重点

1. 从“概念介绍”转向“方法设计”。
2. 把知识组织、实体关系抽取、图增强索引、双层检索、防幻觉约束写成连续的方法链。
3. 强调当前原型与 LightRAG 的对应关系，说明论文中 V-KG RAG 的落地基础。
4. 对无法从项目中证实的实现细节避免硬写；必要时保留明确占位符。

### 第四章修改重点

1. 把系统实现与实验分析并入一章，增强完整性。
2. 系统实现部分以当前评测原型和 LightRAG 服务能力为基础，不再写与项目不符的旧系统设想。
3. 实验部分使用现有最终结果，重写为：
   - 数据集说明
   - 评分维度说明
   - 整体结果对比
   - 分维度分析
   - 分问题类型分析
   - 典型案例与失败案例
4. 结果数值以 `fixed_evaluation_progress.jsonl` 为准。

### 第五章修改重点

1. 工作总结按“研究内容对应回收”的方式重写。
2. 展望不只保留“多模态”一个方向，而要补成更完整的三类不足：
   - 知识覆盖与更新能力
   - 多模态扩展
   - 可信性与评测机制进一步完善
